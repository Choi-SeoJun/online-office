- The user wants ongoing work managed in GitHub: `https://github.com/Choi-SeoJun/online-office`.
- Fetch `github/main` before changes and inspect local changes before switching branches. Preserve user work and never force-push without explicit instruction.
- Implement and verify changes on a focused branch, commit them and update GitHub as part of completing an authorized task. Keep `main` as the current working product unless the user requests a pull-request-only workflow.
- The existing Site is the public, anonymous-play deployment, explicitly requested by the user. Use the shared/public Sites publish flow, not the owner-private shortcut. Preserve its project ID and audience, and use the supported Sites source/build/publication workflow when updating the playable site. Synchronize the same source commit to GitHub and the hosting source.
- Keep credentials, generated builds, dependencies and local runtime files out of Git. Preserve the Korean UI, existing solo play, and the user-authorized invite-based multiplayer mode (up to 16 participants with text chat).

- The user explicitly approved making this repository, source and history public for free GitHub Pages deployment. The primary player URL is `https://choi-seojun.github.io/online-office/`; keep the repository/account names. Its Actions workflow builds the static frontend on main updates. Preserve the Sites deployment as the multiplayer API and original play URL, and deploy backend changes there as well.

Authorize the page and every admin API operation with hosted identity plus `FEEDBACK_ADMIN_EMAIL`; never expose this value or `FEEDBACK_RATE_SECRET` in source or client builds. Public submission CORS does not apply to admin reads or updates. Feedback records must survive room expiry.

- Keep player-facing release notes in `game/updates.ts` current for each published user-facing change. Group by the **Asia/Seoul calendar date**, with one `YYYY-MM-DD` entry per day: append/revise that day's `added` and `fixed` lists for subsequent same-day deployments; create a new entry only on a new day. Describe completed changes in clear Korean, omit implementation details and private feedback contents, and preserve older dates. The latest updates dialog appears in both solo/multiplayer entry and gameplay and invites users to the existing private suggestion form. Do not create a separate notice or unread badge per build.
